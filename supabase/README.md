## Первая настройка проекта

1. Ключи шифрования (один раз на проект, понадобятся при включении шифрования номеров, решение 10 ноября): `openssl rand -hex 32` дважды, хранить в двух независимых местах. Vault не переезжает вместе с дампом базы: `select vault.create_secret('<КЛЮЧ_1>', 'identifier_enc_key', 'Шифрование номеров счетов');` и `select vault.create_secret('<КЛЮЧ_2>', 'identifier_hmac_key', 'HMAC для поиска по номерам');`. Ключи разные. (Шифрование перейдёт в приложение, раздел «Решения».)
2. Миграции по списку выше.
3. Authentication → Users → Add user (email и пароль). Доступ к счетам даёт запись в `account_access`; новые счета из приложения получают доступ при создании, для загруженных извне: `insert into public.account_access (account_id, user_id, role) select id, '<UUID_ПОЛЬЗОВАТЕЛЯ>', 'owner' from public.accounts on conflict do nothing;`

## Что важно знать клиенту

- `account_identifiers`: запрашивать только `id, account_id, kind, last4, valid_from, valid_to`; `select *` вернёт «permission denied» (номера закрыты).
- Жёсткого удаления операций у клиента нет: удаление это `deleted_at`. Насовсем помеченные записи удаляет закрытие периода по выбору владельца.
- Закрытие периода общее; логика в ядре (`src/core/period.ts`), а не в SQL. Триггеры `b_period_lock` в базе остаются защитным слоем.
- Запись из приложения идёт через `rpc('apply_batch', ...)`: одним пакетом, всё или ничего. Права проверяет RLS (security invoker).
- Ошибка закрытого периода начинается с `PERIOD_LOCKED:`.
- Курс: `1 base = rate quote`; остаток на дату считается до конца дня в поясе счёта; округление только при пересчёте.
