## Проверка после применения (в SQL Editor)
```sql
select proname from pg_proc where pronamespace = 'public'::regnamespace;   -- ожидается 0 строк
select tgname, tgrelid::regclass from pg_trigger
 where not tgisinternal and tgrelid::regclass::text like 'public.%';      -- только z_touch
select proname from pg_proc where pronamespace = 'app_private'::regnamespace order by 1;
-- ожидается: account_role, can_read, can_write, handle_new_user,
--            is_account_owner, is_any_owner, is_project_owner, touch_updated_at
```
Если в первом запросе остались функции, значит сигнатура в базе отличается от `db-schema-iteration-1.md`: сообщить Claude, он поправит `drop function`.

## Что проверено в песочнице (чистый Postgres)
- Обе миграции применяются по порядку, без ошибок.
- После второй миграции в `public` нет функций, из триггеров остаются только `z_touch`.
- Весь seed загружается (20 счетов, 45 контрагентов, 25 признаков счетов и т.д.), ссылки по ключам сходятся.
- Отклоняются: расход со знаком плюс, вторая начальная корректировка на счёт, неизвестная плановость, «свой счёт» без `account_id`, обычный контрагент со счётом, номер без хэша в признаках контрагента, тег с несуществующей группой, операция с несуществующим контрагентом.

## Ограничения проверки
- Схема итерации 1 восстановлена по `db-schema-iteration-1.md` (файлов миграций итерации 1 у Claude нет), функции с логикой заменены заглушками.
- Ограничение непересечения признаков (`EXCLUDE ... gist`) в песочнице не проверялось: нет расширения `btree_gist`. Миграции его не меняют.
- Политики RLS проверены только на создание, не на поведение под ролью.

## Решения этой сессии
- Проект «Жена» (счета, которыми пользуется только жена). Часовой пояс страны обязателен, значение `default` берёт пояс из настройки `default_timezone` (сейчас Europe/Bratislava). Базовая валюта EUR в настройках.
- Плановость: справочник `plan_types` (planned, unplanned), пока два значения.
- Freedom Finance: счёт USD без страны (`none`), режим «только остатки».
