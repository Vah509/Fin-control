# Архитектура

Принцип: **вся логика в TypeScript, база только хранилище.** Экраны вызывают только ядро; ядро обращается к базе только через интерфейс `Storage`. Ни экраны, ни ядро не знают про Supabase, таблицы и RLS. Конечная цель: Android (Capacitor) с локальной SQLite, тот же код; Supabase станет необязательным облаком.

## 1. Слои и папки

```
src/core/      правила (чистый TypeScript, без React и без Supabase)
src/data/      types.ts (типы), storage.ts (интерфейс), supabase/ (сейчас), memory/ (тесты), sqlite/ (позже, нет)
src/auth/      вход email+пароль, роль владельца
src/ui/        app.tsx (контекст), parts.tsx, format.ts, hooks.ts, screens/*
src/App.tsx    корень: вход, загрузка справочников, нижние вкладки, ярлыки PWA (?go=snapshot|balance)
tests/         тесты ядра на памяти, контрактные тесты хранилищ, ui-format, integration/ (живой Supabase)
supabase/migrations/   схема и права (без бизнес-правил)
public/        manifest.webmanifest (2 ярлыка), иконки
```

## 2. Соглашения

- Суммы: целые минорные единицы (`number`, safe integer) плюс код валюты. Курсы: десятичные строки, умножение и деление через `bigint` (`money.ts`). Float нигде.
- Время: ISO 8601 UTC; «конец дня» считается в поясе счёта (пояс счёта, иначе пояс страны, `default` берёт `default_timezone` из настроек).
- Ошибки: `CoreError` с кодом (`errors.ts`), сообщение начинается с кода. Коды одинаковы при любом хранилище. Ошибки хранилища: `STORAGE: ...`.
- Запись только онлайн. Запись нескольких записей атомарно: `Storage.applyBatch` (Supabase: `rpc('apply_batch')`).
- Удаление операции = `deleted_at` (мягкое); жёсткое только при закрытии периода по выбору владельца.
- Идентификаторы создаются на клиенте (`ctx.newId`), читаемые `key` у справочников (`keys.ts`).

## 3. Модули ядра (`src/core/`)

| Файл | Что делает |
|---|---|
| `context.ts` | `CoreContext`: хранилище, актор (`userId`, `isOwner`), часы, генератор id, шифрование полей |
| `money.ts`, `time.ts` | минорные единицы, разбор и форматирование, курсы как дроби, локальные дни и пояса |
| `settings.ts` | настройки (`base_currency`, `default_timezone`, `fx_pivot_currency`), пояс счёта |
| `fx.ts` | `FxResolver`: прямая, обратная пара, через опорную валюту; приоритет источников; «нет курса» |
| `transactions.ts` | проверки формы операции, создание, правка, мягкое удаление и восстановление; запись в журнал для корректировок |
| `balance.ts`, `balanceEntry.ts` | расчётный остаток; форма ввода остатка (предпросмотр, корректировка на разницу, контрольная точка) |
| `checkpoints.ts` | контрольные точки, расхождения с расчётом |
| `snapshot.ts` | срез на дату, итоги по валютам и в одной валюте, группировки, «неучтённое» |
| `locks.ts`, `period.ts` | общее закрытие периодов: блокировка правок, закрытие (очистка `raw`, удаление помеченных, проверка расхождений), открытие, журнал |
| `accounts.ts`, `projects.ts`, `keys.ts`, `appearance.ts` | создание и правка счетов и разделов, порядок, перенос, архив, цвета и иконки |
| `identifiers.ts`, `crypto.ts` | признаки счетов (нормализация, HMAC, непересечение сроков, поиск по дате); шифрование WebCrypto. **Ключей пока нет**: решение 10 ноября |
| `dump.ts` | выгрузка (JSON, только владелец) и загрузка-слияние по id (запрещена при действующем закрытии) |
| `audit.ts`, `errors.ts` | записи журнала, коды ошибок |

Правила, проверяемые ядром: знак суммы по типу, ненулевая сумма, валюта операции = валюта счёта, исходные сумма и валюта вместе и с тем же знаком, архивный счёт не принимает операции, одна начальная корректировка на счёт, правка только в открытом периоде, только владелец закрывает и выгружает.

## 4. Интерфейс хранилища (`src/data/storage.ts`)

`list(entity)` для небольших таблиц; `getTransaction`, `listTransactions(query)`, `listCheckpoints`, `listAccountIdentifiers`, `listPeriodLocks`, `listFxRates`, `listAudit`; `applyBatch(batch)` (upsert по ключу, удаление операций, записи журнала, выдача доступа владельца новым счетам); `exportAll`, `importAll` (полная замена; Supabase не поддерживает и бросает `STORAGE`).
Реализации: `memory/` (тесты и эталон), `supabase/` (`supabaseStorage.ts`, `columns.ts` перевод строк и денег, страницы по 1000 строк), `sqlite/` (шаг 10).
Контрактные тесты `tests/storage-contract.ts` запускаются на каждом хранилище.

## 5. Экраны (`src/ui/screens/`)

Home (итог на сегодня, расхождения контрольных точек), Snapshot (срез на дату и группировки), Balance (ввод остатка), Moves (просмотр 100 последних операций за 30 дней, без ввода), Accounts (разделы, порядок, перенос, архив), Account (карточка: название, раздел, цвет, иконка, архив), NewAccount, More, Periods (закрытие и открытие), Dump (выгрузка и загрузка файла), Login.

## 6. Тесты

91 тест, 11 файлов, vitest. Ядро проверяется на `memory/`; `supabase-mappers` проверяет перевод строк; `integration/supabase.int.ts` (контракт на живой базе) запускается вручную и пока не запускался.
SQL-проверки итерации 1 (90 штук, из старого справочника) перенесены в тесты ядра как сценарии.

## 7. Развёртывание

Cloudflare Pages собирает из репозитория; переменные `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`. Вход один раз созданного пользователя Supabase; роль владельца берётся из `account_access`. Защита данных пока: RLS и вход; правила в коде защищают от ошибок, не от злоумышленника.
