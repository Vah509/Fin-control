# Fin-control: состояние проекта (обновлено 13 ноября 2026)

**Точка входа для любого нового чата.** Читать целиком, затем файлы из раздела 9 по необходимости.
Где этот файл и документы `docs/` расходятся с брифом v2, дополнением v3 (файлы проекта Claude) и `db-schema-iteration-1.md`, **верны `docs/`**. Актуальная схема базы: `docs/DATA-MODEL.md` и `supabase/migrations/`.

## 1. Что это

Личное приложение учёта денег в разных местах, странах и валютах. Главный сценарий: срез остатков на выбранную дату. Второй: движения (откуда пришло, куда ушло).
Владелец: Вахтанг (Братислава). Работает **с телефона** (git и компьютера нет), общается по-русски, коротко.

## 2. Как продолжить в новом чате

Первая фраза владельца: «Прочитай docs/STATUS.md в репозитории Vah509/Fin-control (клонируй) и продолжи с пункта N из раздела 6».
Что делает Claude: клонирует `https://github.com/Vah509/Fin-control.git`, читает этот файл, `docs/WORKFLOW.md` (правила работы и состав ZIP) и нужные документы, запускает `npm ci && npm run build && npx vitest run`, сверяет результат с разделом 4. Если не сходится, сначала правит документацию и сообщает владельцу.

## 3. Репозиторий

- Адрес: https://github.com/Vah509/Fin-control. Стек: Vite + React + TypeScript, Supabase (Postgres, Auth, RLS), Cloudflare Pages.
- Проверка: `npm ci`, `npm run build` (включает `tsc`), `npx vitest run` (**91 тест**, 11 файлов; на 13.11.2026 всё зелёное). `npm run test:supabase` против живой базы нужны переменные `TEST_SUPABASE_URL`, `TEST_SUPABASE_ANON_KEY`, `TEST_USER_EMAIL`, `TEST_USER_PASSWORD`; пока не запускался.
- Cloudflare Pages: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` (publishable-ключ). Сервисный ключ нигде не используется.
- Тестовый проект Supabase: Test-fin-cintrol (Ireland). Рабочего проекта нет. В тестовой базе загружен seed (20 счетов, 45 контрагентов, 18 тегов в 10 группах, 2 стартовые корректировки). Репозиторий публичный: seed и личные данные в него не кладутся.
- Доставка изменений, состав ZIP и правила актуальности документов: `docs/WORKFLOW.md`.

## 6. Ближайшие шаги (подробно в `docs/ROADMAP.md`)

0. **Наведение порядка** (состояние живой базы, уборка мёртвых функций, seed вне GitHub).
1. **Коррекции существующих функций** (раздел 2 дорожной карты).
2. **Загрузка движений, шаг 5** (раздел 3): ввод вручную и наличных, переводы и обмен, фирмы, импорт выписки JSON со сверкой, очередь «разобрать».
3. **Выгрузка** (раздел 4): шифрование паролем, автокопия, напоминание, выгрузка движений в CSV.
4. Дальше по плану: теги и анализ (6), курсы (7), портфель (8), автоматизация выписок (9), SQLite и Capacitor (10-11).
