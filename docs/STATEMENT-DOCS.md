# Выписки как документы и отдельное встраивание в учёт

Состояние на 27.11.2026: **решение владельца принято, проект написан, код и миграции не менялись (версия 0.2.36).** Схему утверждает владелец перед реализацией (этап 1). Заменяет план `ANCHORS.md` «записывать операции при загрузке»: остатки и расчёт из `ANCHORS.md` (таблица `balance_periods`, точки отсчёта) остаются и становятся результатом встраивания (этап 2).

## 1. Идея
Загрузка выписки только **сохраняет документ банка** (разобранный, с контрагентами и тегами). Никаких сверок с учётом, блокировок и перезагрузок: если файл разобран и сошёлся со своими итогами, он сохраняется. Встраивание документов в учёт (операции, остатки, пары переводов, дыры) делает **отдельная процедура, только по кнопке**, позже. Ручной ввод (наличные, без выписок) тоже документ, тип `manual`, без остатков.

## 2. Таблицы (предложение на утверждение)
- `statement_documents`: `id`, `kind` (`statement` / `manual`), `institution_id`, `file_name`, `file_hash` (уникален среди документов; повторная загрузка того же файла отклоняется), `period_start`, `period_end` (период выписки по шапке, не равен датам первой и последней операции), `parser`, `created_by`, `created_at`.
- `statement_accounts`: `id`, `document_id` (удаление документа удаляет и эту строку), `account_id`, `period_start`, `period_end`, `opening_balance`, `closing_balance` (у `manual` пусто), `currency`, `total_income`, `total_expense`, `built_in_at` (пусто = не встроен). Выписка по нескольким счетам (ПриватБанк) даёт несколько таких строк на один документ.
- `statement_rows`: `id`, `document_id`, `statement_account_id`, `n`, `booked_at`, `value_date`, `amount` (со знаком), `currency`, `original_amount`, `original_currency`, `counterparty_id`, `description`, `row_key`, `duplicate_of` (ссылка на `statement_rows.id`, `on delete set null`), `transfer_hint`. Поле `raw` не хранится (персональные данные).
- `row_marks`: `account_id`, `row_key`, `tag_id`, `plan_type`, `comment` (ключ `(account_id, row_key)`). Правки на конкретной операции хранятся отдельно от документа: удалили документ, загрузили заново, правки подтянулись по ключу. Контрагенты и их теги по умолчанию остаются в своих таблицах.
- `transactions` получит ссылку `statement_row_id` (когда строка документа встроена; убрать документ из учёта = удалить операции с этой ссылкой). Этап 2.
- `balance_periods` (уже есть, шаг 5б) заполняется встраиванием: точки отсчёта остатков.

**Ключ строки** `row_key` = sha256 от `счёт | момент | сумма в копейках | валюта | описание без лишних пробелов | номер среди одинаковых в выписке`. Нужен, чтобы находить дубли и привязывать правки. Если банк поменяет формат описания, ключ поменяется и правки не подхватятся (риск принят; поля ключа берутся стабильные).

## 3. Дубли при загрузке
1. Тот же `file_hash`: отказ «уже загружена».
2. Все строки уже есть у других документов (по `row_key`): отказ «записано не будет, все строки уже в базе».
3. Часть строк есть: документ сохраняется целиком, у строк-дублей `duplicate_of` указывает на уже существующую строку. У оригинала пометки нет.
4. Удалили оригинал: `duplicate_of` обнуляется сама, строка стала обычной. Встраивание пропускает строки с `duplicate_of`. Ручной ввод и банковскую запись по одним деньгам система сама не сопоставляет.

## 4. Правила документа
- Документ **не редактируется**, его можно удалить. Удалить можно, только если он не встроен (`built_in_at` пусто); встроенный сначала «убрать из учёта». Закрытый период: ни встраивать, ни убирать.
- Остатки на экранах счёта и срезе показываются **только по встроенному**; несвязанные документы в расчёт не входят, видно счётчик «не встроено: N».
- Размер: операция около 305 байт, разобранная выписка из 26 строк около 12 КБ; десятки лет в пределах лимита 500 МБ. В выгрузку попадают новые таблицы (учесть в `dump.ts`).

## 5. Экран «Выписки»
Список документов (аккордеон). Заголовок: банк и период (для `manual` — дата ввода). Раскрытие: по каждому счёту отдельная раскладка (остаток на начало и конец, приход и расход за период, число строк, `встроен/не встроен`), кнопка скачать XLSX (формат `STATEMENT-XLSX.md`), кнопка удалить. Позже на экране счёта кнопка «Выписки счёта» (только документы этого счёта).

## 6. Этапы
1. Миграция (4 таблицы, индексы, RLS, `apply_batch`), `src/data` и ядро `statementDocs.ts`: сохранить документ из задачи (шаги 1-3 остаются), проверка дублей, экран «Выписки», замена шагов 4-5 задачи на «Сохранить выписку», удаление документа, XLSX документа. Таблица `statement_problems` и сравнение шага 4 станут не нужны (убрать отдельно).
2. Встраивание (кнопка): по счёту, по порядку периодов; подряд, дыра (точка отсчёта в `balance_periods`), пересечение, пары переводов между своими счетами, `statement_row_id`; расчёт остатка из `ANCHORS.md` (шаг 5в), срез и экран счёта.
3. Ручной ввод как документ (экран «расход / приход», несколько строк, «Записать»).
4. «Выписки счёта», проверка целостности по всей базе, закрытие периодов.
