## 2026-11-24 (52): «Передвинуть начальный остаток», настоящая причина, версия 0.2.26
- Исправление 0.2.25 не помогло. Настоящая причина (найдена по `pg_get_functiondef` в тестовой базе): `apply_batch` сначала вставляет новые строки таблицы, потом обновляет существующие, порядок строк в пакете не важен. Новый начальный остаток вставлялся раньше понижения прежнего (`uq_transactions_opening`). Теперь два пакета подряд: сначала понижение или удаление прежнего остатка, потом вставка нового (`openingFix.ts`). Не атомарно: при сбое второго пакета начального остатка нет, повтор предложит «Создать». Миграций нет. Тест: `openingfix.test.ts`. В базе проверено: по SPACE одна запись, начальный остаток 1245.58 на 01.10.2026 00:00, движений нет (выписка не записана).
- Урок: тесты на хранилище в памяти не ловят ограничения Postgres; нужен контрактный тест на живой базе (долг).
