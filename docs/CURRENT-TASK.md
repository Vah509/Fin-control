# Текущее задание: импорт выписок ПриватБанка (старт в новом чате)

**Как пользоваться (всегда).** Новый чат начинается так: «Прочитай docs/STATUS.md в репозитории Vah509/Fin-control (клонируй) и продолжи с первого неотмеченного пункта docs/CURRENT-TASK.md».
**Правило отметок.** Когда пункт реализован, в этом же ZIP его строка меняется с `[ ]` на `[x]` и получает дату и короткую пометку (что проверено). Частично сделанный пункт остаётся `[ ]` с пометкой «сделано: ..., осталось: ...». «Проверено владельцем на телефоне» отмечается только по его подтверждению.

## Решение владельца 14.11.2026
Начинаем с реального примера: владелец загружает в новом чате выписки **всего ПриватБанка сразу** (все его карты и счета), Claude разбирается на них, и по ним проектируется контракт JSON и импорт. Порядок: 5.0 (таблицы `imports`, `import_rows`) → 5.4 (импорт JSON со сверкой; счёт выбирается вручную, поиск по номеру позже) → 5.1 → 5.2 → 5.3 (`docs/ROADMAP.md`, раздел 3). Защита от повторной загрузки (`dedupe_hash`) по предложению в `docs/DECISIONS.md`, раздел 3, п. 3 (утверждение владельца ждёт ответа в чате).

## Пункты
- [ ] 1. Владелец присылает выписки ПриватБанка (лучше Excel или CSV, иначе PDF; все счета банка: «Універсальна» 4402/9335, «Універсальна» 0380 и др., «Інтернет картка» …1123, «Скарбничка», жена «Картка для виплат» …0444). Номера счетов, паспортные и налоговые данные закрыть; файлы в GitHub не класть (репозиторий публичный).
- [ ] 2. Claude разбирает формат: какие поля есть, как выглядят переводы между своими счетами, валюта карты и операции, комиссии, внутренние переводы «Скарбнички»; решает, нужен ли промпт для чата или парсер на готовых файлах (Excel/CSV).
- [ ] 3. Контракт JSON под реальные данные (уточнение контракта брифа v2 §6) и промпт, если нужен.
- [ ] 4. Миграция 5.0 (`imports`, `import_rows`, без логики) и ядро импорта (zod, дубли, сверка до копейки, пакетная запись, очередь «разобрать»), тесты на памяти.
- [ ] 5. Экран «Импорт выписки»: загрузка JSON, выбор счёта, предпросмотр, подтверждение.
- [ ] 6. Проверка на реальных данных владельцем; при успехе остальные банки (monobank, Slovenská sporiteľňa, Revolut) по тому же образцу.

## Открытое
Подтверждение `dedupe_hash` и ручного выбора счёта на первом этапе (ждёт ответа владельца). Ключ шифрования номеров (вопрос 7) откладывается до поиска счёта по номеру.
